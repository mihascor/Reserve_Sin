# Конфигурация

## Статус

В репозитории есть пример серверных параметров [server/reserve.env.example](../server/reserve.env.example) без секретов. Для production его значения переносятся в `/etc/reserve-sin/reserve.env`; настоящий API-токен в пример не добавляется. Android-экран синхронизации позволяет задать HTTPS-адрес и токен; токен шифруется AES-GCM, а ключ хранится в Android Keystore.

## Подтверждённые параметры

| Параметр | Требование ТЗ |
| --- | --- |
| Адрес сервера в Android | По умолчанию `https://reserve-sin.duckdns.org`; пользователь может изменить его в настройках. |
| API-токен | Один постоянный Bearer-токен. Генерируется случайно, хранится на сервере в отдельном env-файле, вводится при первоначальной настройке Android и защищается Android Keystore. |
| API-адрес | Go API слушает только `127.0.0.1:8080`. |
| Путь к SQLite | `RESERVE_SIN_DATABASE_PATH`; в production — `/var/lib/reserve-sin/reserve.db`. |
| Bearer-токен сервера | `RESERVE_SIN_API_TOKEN`; обязательное случайное значение, отсутствует в примере env. |
| Публичный доступ | HTTPS через Caddy; для API не допускается незащищённый HTTP. |
| Серверные пути | Исполняемый файл `/opt/reserve-sin/reserve-server`, база `/var/lib/reserve-sin/reserve.db`, копии `/var/backups/reserve-sin/`. |

## Логирование сервера

| Переменная | Значения | По умолчанию | Назначение |
| --- | --- | --- | --- |
| `RESERVE_SIN_ENV` | `development`, `production` | `development` | В `development` используется читаемый текстовый формат, в `production` — JSON. |
| `RESERVE_SIN_LOG_LEVEL` | `debug`, `info`, `warning`, `error` | `info` | Минимальный уровень выводимых записей. |

Неизвестное значение параметров логирования останавливает запуск сервера с сообщением об ошибке конфигурации. `RESERVE_SIN_API_TOKEN` обязателен: сервер не запускается без него. Параметры не содержат секретов, кроме самого токена, который не добавляется в пример конфигурации.

Если `RESERVE_SIN_DATABASE_PATH` не задан, сервер использует `reserve.db` в текущем каталоге. Для production переменная обязательна на практике: укажите целевой путь из таблицы выше в `/etc/reserve-sin/reserve.env`. Значения `:memory:` и SQLite URI `file:` допустимы только для локальной разработки и тестов.

Токен нельзя включать в исходный код, Git, логи или документацию. После сохранения Android не отображает его и не хранит в открытом виде в DataStore. Адрес Android допускает только HTTPS без пути и query-параметров; пустое поле токена при сохранении адреса оставляет сохранённый токен неизменным. Доступ к env-файлу и базе должен быть ограничен системным пользователем `reserve-sin`.

## Запланированная конфигурация веб-интерфейса

Caddy будет защищать `/app/*` и `/app-api/*` Basic Auth для одного пользователя. В конфигурации Caddy допускается только хеш длинного уникального пароля, полученный штатной командой Caddy; открытый пароль не хранится в Git, Caddyfile или документации.

Чтобы Caddy добавлял Bearer-заголовок к запросам `/app-api/*`, процесс Caddy должен получать `RESERVE_SIN_API_TOKEN` через отдельный защищённый системный механизм конфигурации. Значение не добавляется в репозиторий и не передаётся браузеру. Перед реализацией нужно определить владельца и права этого файла с учётом пользователя systemd-сервиса Caddy.

Требования к SQLite (`WAL`, `foreign_keys`, `busy_timeout`) приведены в [документации базы данных](database.md); порядок применения конфигурации — в [развертывании](deployment.md).
