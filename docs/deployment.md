# Развертывание и резервное копирование

## Статус

Инструкции ниже описывают целевое окружение из ТЗ. Начальная SQLite-миграция уже применяется сервером при запуске, но файлов сервиса, Caddy, готового production-бинарника и скриптов резервного копирования пока нет, поэтому готовой последовательности команд публикации не существует.

## Целевое размещение

Сервер должен работать на Ubuntu 24 без Docker для Reserve_Sin. Go-сервис запускается от отдельного системного пользователя `reserve-sin` через systemd, с автоматическим запуском после перезагрузки и перезапуском после ошибки. Логи ведутся в journald и не должны содержать API-токен или полные тела конфиденциальных запросов.

Для production в `/etc/reserve-sin/reserve.env` нужно задать `RESERVE_SIN_ENV=production` и выбрать `RESERVE_SIN_LOG_LEVEL`. `slog` записывает JSON в stdout, а systemd/journald собирает его как стандартный вывод процесса. Смотреть записи следует через `journalctl -u reserve-sin`; отдельное внешнее хранилище логов не используется и его отказ не влияет на работу приложения.

| Ресурс | Целевое расположение |
| --- | --- |
| Бинарник | `/opt/reserve-sin/reserve-server` |
| SQLite | `/var/lib/reserve-sin/reserve.db` |
| Конфигурация и токен | `/etc/reserve-sin/reserve.env` |
| Резервные копии | `/var/backups/reserve-sin/` |

Go API слушает только `127.0.0.1:8080`. Caddy публикует `https://reserve-sin.duckdns.org` и проксирует запросы к нему. Снаружи нужны только порты `80` и `443`; существующие порты AmneziaVPN не изменяются. Права должны ограничивать доступ посторонних пользователей к env-файлу, базе и резервным копиям.

## Резервное копирование и восстановление

ТЗ требует ежедневную автоматическую копию SQLite, хранение нескольких последних копий, удаление старых по сроку (рекомендовано 14 дней), журналирование результата и ручной запуск. Для активной базы в WAL запрещён обычный `cp`; допустимы SQLite backup API или `VACUUM INTO`.

Процедура восстановления и конкретные команды пока не могут быть подготовлены: не определены механизм запуска копирования, имена файлов, unit/timer и версия используемой SQLite. После их добавления нужно документировать остановку или безопасный режим восстановления, проверку целостности и права восстановленного файла.
