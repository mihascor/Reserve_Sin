# ADR 001: local-first учёт на основе истории операций

**Статус:** предусмотрено ТЗ, не реализовано.

## Решение

Android-приложение хранит данные интерфейса локально в Room. Каждое изменение остатка записывается отдельной операцией; строки групповой операции имеют общий `batch_id`. Остатки вычисляются из неотменённых операций, а отмена выполняется мягко через соответствующий признак.

Для синхронизации используются уникальный `client_operation_id`, статусы локальной синхронизации и серверная revision. Неудачные отправки повторяет WorkManager.

## Обоснование

Это обеспечивает отображение локальных данных и сохранение операции без интернета, при этом повторная отправка не должна создавать дубликат.

## Следствия

Нужны локальная база, серверная идемпотентность, синхронизация изменений по revision и правила исправления уже синхронизированных операций. Конкретное разрешение конфликтов ТЗ не определяет.
