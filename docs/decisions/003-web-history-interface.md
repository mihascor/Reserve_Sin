# ADR 003: закрытый read-only веб-интерфейс истории

**Статус:** принято и реализовано.

## Решение

Веб-интерфейс Reserve_Sin состоит из статических файлов HTML, CSS и Vanilla JavaScript в `web/app/`, которые обслуживает Caddy. Node.js, npm и клиентские фреймворки не используются.

Первая страница `/app/` — read-only таблица «Движение средств» в тёмном оформлении, согласованном с GitHub. Она показывает неотменённые операции активных категорий: дату, категорию, метку, комментарий, приход, расход и признак групповой операции. Операции архивных категорий в эту таблицу не включаются. Операция активной категории с архивной меткой остаётся в выдаче: API возвращает имя сохранённой метки, чтобы не терять исторический контекст.

Доступ к `/app/*` и `/app-api/*` защищается Caddy Basic Auth для одного пользователя. Пароль хранится только в виде криптографического хеша; доступен только HTTPS.

Браузер обращается только к относительным URL `/app-api/*`. Caddy после успешной Basic Auth заменяет клиентский заголовок `Authorization` на внутренний `Bearer` с `RESERVE_SIN_API_TOKEN` и проксирует запрос к Go API на `127.0.0.1:8080`. API-токен не передаётся JavaScript, HTML, логам или ответам браузеру. Маршрут `/api/v1/*` сохраняет существующую Bearer-защиту для Android.

Для веб-истории выделен отдельный read-only маршрут `GET /api/v1/web-history`, а семантика существующего `GET /api/v1/transactions`, используемого Android, не изменена. Он поддерживает постраничную выдачу и возвращает только данные, определённые этим решением.

## Обоснование

Статическая страница не требует нового сервера, контейнера или сборочного контура и использует текущую SQLite-базу вместе с Android-приложением. Отдельный маршрут исключает скрытое изменение поведения мобильного клиента. Передача Bearer-токена только между Caddy и локальным Go API не позволяет извлечь его из браузера.

## Следствия

Статические файлы веб-интерфейса, Caddy-маршруты, защищённая серверная конфигурация Caddy с хешем Basic Auth и API-токеном вне Git, а также серверные тесты фильтрации, пагинации и авторизации реализованы. При неуспешной загрузке интерфейс показывает HTTP-код ответа, если сервер его вернул; успешная загрузка всегда скрывает сообщение об ошибке. Веб-интерфейс первой версии не создаёт, не изменяет и не отменяет данные.

## Нерешённые вопросы

- Фильтры, поиск, экспорт и редактирование не входят в первую версию и требуют отдельного решения.
